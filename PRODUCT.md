# SSC Insight

SSC Insight is a personal SSC mock tracker and preparation system. It helps an aspirant record exam-specific results, understand performance over time, schedule the next piece of work, and compare improvement. The public `/` route explains the product and carries the only Google sign-in entry; verified accounts redirect to `/dashboard`. There is no separate sign-in page.

The landing uses a modern Merit Gazette to explain one result becoming a useful action: an illustrative record is captured, read at the correct scope, turned into dated work, and compared with the next attempt. Product scenes are rendered in code and preserve the real result, performance, calendar and comparison terminology; one original editorial aspirant illustration supplies human context. The Gazette identity is independent from authenticated workspace themes, while the shared SI record mark and Source Serif headings connect both surfaces. CGL, CHSL, MTS, CPO, GD Constable, Stenographer, Selection Post and custom patterns remain under one exam-aware system. Public figures are labelled illustrative.

## Audience and access

SSC aspirants sign in with Google and work in isolated private accounts. Each user can access and change only their own mocks and settings. Anonymous visitors must sign in before entering the dashboard.

## Core workflows

- Log, edit, inspect, and delete mock attempts with platform, date, subject breakdown, optional timing, rank, percentile, and notes. Deleting moves the attempt to Trash rather than destroying it.
- Track full mocks, single-subject mocks, and sectional mocks against the exam tier you actually sat. Each tier's pattern (subjects, question counts, maximum marks, marking scheme, duration and any sectional split) comes from the official SSC notice and is recorded on the attempt when you save it, so a later catalog correction never changes a past result. SSC CGL and CHSL, MTS, CPO, GD Constable, Stenographer and Selection Post are built in; you can also define a custom exam with its own tiers. On CGL Tier 2, Computer Knowledge is a qualifying subject scored separately whose time still counts towards the overall time, and Section III is a qualifying section rather than merit.
- Log a date without a time, choose a platform preset or enter a custom platform, and enter durations using three hour/minute/second blocks. Scores update live from question counts; overall time is calculated automatically. Empty time blocks become zero.
- Review history using type, subject, platform, date, and text filters. Compare two to four attempts, using percentages where maximum marks differ. Active filters and the dashboard scope are mirrored into the page address, so a bookmarked or shared link restores the same filtered view after signing in; browser Back moves between pages, not between filter states.
- Paste a result report into a reviewable form before saving; preserve manual correction and explicit review. An optional AI helper can arrange the pasted report into a draft, but the user must apply it and review every field before saving.
- Generate an optional AI coaching read of saved performance and ask follow-up questions in a session-only chat panel. The panel knows which screen and plan date you are viewing (shown as a small context chip) but receives no attempt details beyond the standard analysis context. The coach is read-only; it never creates, edits, deletes, or schedules records.
- Configure the AI provider yourself from Settings → AI provider, or directly inside the AI panel when it is not yet set up. Choose a preset (OpenAI, OpenRouter, Groq, Together, DeepSeek, or a local Ollama) or a custom OpenAI-compatible endpoint, enter an API key, then fetch, search, and select a model from the provider’s catalog. An exact model ID can also be entered manually. Test the draft connection before saving; the test sends one small completion, may incur a small provider charge, and does not save changes. A key you enter is encrypted before it is stored, is never shown back to you (only its last four characters), is never written to a backup, and can be removed at any time. Leaving the key blank reuses a saved key only for the same provider and endpoint; changing either requires a new key. Model discovery and draft testing run on the server without persisting the draft. The server may also provide a shared configuration, which yours takes precedence over.
- See score trends, question breakdowns, subject strengths, accuracy, timing, and target progress. Missing values remain unknown rather than becoming zero.
- Dashboard tabs switch the analytical grain rather than filtering the saved-record table. Full Mocks projects saved full mocks. Subject Wise projects every subject result from full, sectional, and standalone subject mocks, with all subjects shown together. Sectional Wise projects explicit sectionals plus Section I (Quant + Reasoning) and Section II (English + General Awareness) derived from each full mock. All Mocks projects every saved attempt exactly once and compares percentages across different maxima. A full mock is not additionally counted as its subjects or sections in All Mocks.
- Where you stand is one global subject radar on every tab. Make every attempt count uses reference-led visual outcome cards for the selected analytical grain: one Full Mocks card, one card per populated subject or section, and parent attempts grouped by mock type in All Mocks. Every card shows attempt/question coverage, score percentage, Correct/Incorrect/Unattempted counts and shares, and aggregate marks/max, with a score-centered answer ring, answer-share bars, accuracy, and explicit reported-percentile availability—without percentile borrowing or extra projections. Subject deep dive appears on every tab except Subject Wise.
- Configure targets as three separate things, never conflated. A **percentile goal per exam** records the percentile you are aiming for; the app never computes or estimates a percentile, and never presents one as a selection probability. A **marks target per tier** is validated against that tier's maximum and drawn as a percentage reference on the charts for that tier. A **structure default** is a shared marks target that only tiers with the identical paper can inherit, and any tier can override it or reset back to the inherited default. Percentile, percentage of a paper, raw marks, normalized scores and official cutoffs are always labelled as the different things they are.
- Review performance by attempting date, not by when you recorded it. History and Compare support platform, subject, tier, date-range and text filters with server-side sorting and pagination; a comparison can include up to four results and is addressable by URL. Compare shows each result against the target for its own paper, the move from the previous attempt, and the filtered average, using percentages wherever the papers have different maxima.
- Follow a built-in 50-day study plan (26 Oct – 14 Dec 2026, three phases) imported from the RBE daily-targets PDF. The plan itself is read-only source data; the student's completions, recorded results, revision flags, checklist, and notes are stored separately per account.
- A study calendar covers the whole plan window with month, week, day, and agenda views; every scheduled test keeps its original RBE link. Selecting a date reveals that day's ledger; /plan/<date> is the shareable deep link. A summary strip reports the next scheduled mock, plan completion, this week's load, and how many scheduled mocks are done.
- The calendar is one unified ledger over three toggleable layers. **Plan** is the scheduled work (mocks, sectionals, topic tests, and each day's revision blocks). **Personal** is the student's own dated tasks. **Logged** is every recorded mock result, with its score. Each layer has its own form rather than its own colour: scheduled work is a tinted row with a 2px category rule, personal tasks are an outlined row with a status dot, and logged results are a neutral row with a serif score. One layer is always visible, and the choice survives a refresh through the URL.
- Any date is reachable, including dates before or after the plan; personal tasks and logged results are not bounded by the plan window. Phones open on the agenda — the next two weeks of work, grouped by date with quiet stretches collapsed — and the month grid, week and day views are one tap away. On phones, month and week taps open the day's ledger in a bottom drawer.
- Adding or editing a personal task from the calendar uses the same editor as My Tasks, so a task behaves identically wherever it is opened. The full personal workspace — groups, subtasks, Needs date, filters — stays in My Tasks. Deleted work is recovered from /trash instead, so neither surface keeps its own Trash.
- A daily workspace at /plan/<date> lists the day's assignments with completion, result recording (score, percentile, wrong, unattempted — blank stays unknown), the four daily-checklist habits, the day's revision blocks, and weak-area notes. It also lists the tracker attempts logged for that date.
- Every planner surface offers an Add mock record action that opens the normal mock form prefilled with the selected attempt date (and the scheduled test's name when started from a task). Saving records a normal tracker attempt on its own attempt date. It never creates, moves, or auto-completes a scheduled plan item, and a plan task's own result fields remain the explicit way to record plan progress.
- Attempt dates are distinct from scheduled dates and from recording time. The form labels the field "Attempt date", defaults to today in IST, and the actual attempt date is what history, charts, and date filters use. A mock attempted on a different day than scheduled appears on the day it was actually attempted.
- My Tasks opens directly into the full personal-task workspace, with a month calendar, selected-date list, quick entry, editing, rescheduling, groups, filters, and sorting. The Study Calendar shows the same dated tasks as one layer of its unified ledger. Personal dates are not limited to the mock-plan window.
- Personal todos require a date (no time), with quick title entry, optional notes and priority, reusable groups, and subtasks sharing the parent date. Month browsing and Selected day/Today/Overdue/Upcoming/All/Completed views support paginated lists, search, status/group/priority filters, and priority/date/newest/title sorting. Legacy undated tasks remain in Needs date until assigned a date. Every personal task may carry one optional external link: it is validated to strict http(s), always opens in a new tab with the destination host shown, and never auto-opens.
- Unfinished todos stay on their original dates and become overdue. Within date/group, unfinished items appear first by priority, followed by completed items. Checking a parent completes all its subtasks; unchecking it reopens them all. Completing all subtasks completes the parent, and reopening one reopens the parent. Task status is shown with status dots (todo, in progress, done, derived overdue) that follow the app's semantic tokens — identical across every palette and style.
- Deleting a personal todo moves it and its subtasks to Trash, which holds every deleted record from every module for 15 days. Restoring keeps its original date/details/completion state. Deleting a group moves the group itself to Trash rather than discarding it: its tasks keep their membership and stay visible as Ungrouped until the group is restored, and the group keeps its name while it waits so restoring it can never collide with a new one. Personal todos never alter mock attempts or built-in plan assignments.
- A single Trash page at /trash is the one place deleted work is recovered. It collects deleted mock results, personal tasks, custom exams and task groups in one searchable, sortable, paged list with a type filter that reports each kind's count. Every row states what it was, when it was deleted, and how many days are left. Individual and bulk restore, individual and bulk permanent deletion, and Empty Trash all work from there, and the two irreversible actions always confirm what they will remove — including how many live tasks a purged group will leave ungrouped.
- Deleted records stay recoverable for 15 days from the moment of deletion. At the end of that window the backend stops offering them for restore, whether or not the scheduled cleanup has run; the cleanup job only reclaims their storage. A record past its window cannot be restored by any request, and restoring is never silently extended. Removing a custom exam takes it out of the catalog and the scope switcher while keeping its tiers, targets and percentile goal attached, so restoring it returns the exam exactly as it was; those are discarded only when the exam is permanently deleted. A trashed exam or group holds its name for the 15 days, and the app says so if you try to reuse it rather than failing with a bare conflict.
- Todo assistance in the personal planner and AI panel generates selectable, editable proposals for creation, editing, rescheduling, completion/reopening, or moving to Trash. The user must provide a date or range, review before/after values, then explicitly apply selected changes. Generation itself never mutates data; server-side ownership, record versions, and idempotency protect apply/retry behavior. AI-proposed todos carrying a link are held to the same strict http(s) policy.
- The dashboard shows Overview, Today's Plan, then Study Calendar. Today's Plan combines today's study assignments with personal tasks, a personal mini-calendar, and a distinct overdue preview excluding the selected date. Selecting a personal date changes only personal work; study assignments stay anchored to today. Plan progress, upcoming tests, revisions, recent attempts, coaching, and performance follow these primary sections. Revision completion remains manual.
- Download a portable JSON backup containing all mocks, subject results, notes, ranks/percentiles, timings, overrides, source metadata, and the target score. The file excludes email, user IDs, and credentials, so it can be imported into a different signed-in account.
- Preview an import with merge or replace modes. Merge preserves existing records and skips exact duplicates while reporting content conflicts; replace deletes the current account’s mocks after an explicit safety-backup download and confirmation naming the signed-in account. All imports are atomic. Replace is the one exception to the 15-day rule — it is the only deliberate immediate destruction in the product, and it is why the safety download is mandatory. It never touches Trash, and a backup never carries Trash entries; an import whose record collides with a trashed one restores that entry instead of duplicating it or failing.
- CSV remains a read-only spreadsheet export and cannot be imported. Legacy version-1 backups remain importable; the target is unavailable in them.
- Imports have a 4 MB transport limit. The app does not change the Google login identity and never reassigns ownership server-side; moving to a different Google account means exporting there and importing here.

## AI coach

AI is optional and uses an OpenAI-compatible endpoint configured by the user or through server defaults. When it is unavailable, the tracker remains fully usable and the AI card and assisted-extraction action are hidden or disabled.

- The coach card is generated manually, not on page load. It returns a structured headline, summary, strengths, focus areas, next actions, and caveats.
- Follow-up chat is session-only and held in memory; it disappears on reload, sign-out, account change, or session failure. It is never written to browser storage.
- AI-assisted paste returns an editable draft that distinguishes reported values, safely derived SSC counts, and missing fields. The user reviews or corrects mock details, subject counts, timings, rank, and percentile before choosing **Use reviewed values**; saving remains the existing separate form action. Contradictions and required missing values block copying, while the deterministic paste parser stays available as a fallback.
- Ordinary coaching context is limited to aggregate analytics and the latest 20 full mocks. Mock notes, email, user identity, auth data, and per-attempt detail outside those latest 20 full mocks are never sent. The pasted report is sent only for extraction and is treated as untrusted data.
- Every request is subject to an IST-daily request and token cap. Usage rows log feature, model, token counts, status, and safe error codes, but never prompts, responses, notes, or report text.
- Ordinary coaching and report extraction have no write tools. Todo assistance is a separate mode: it proposes personal-todo operations, and only explicit reviewed confirmation invokes the apply endpoint. Mock records and built-in study-plan assignments cannot be AI mutation targets. Prompt-injected instructions never authorize changes.
- The AI panel has three tabs. **Coach chat** renders answers as a memo: one short headline line, then `WHAT I SEE` and `WHAT TO DO` sections, with light formatting (bold, inline code, bullets, code blocks, bare links shown as host-labeled anchors) and a Copy action per answer. The prompt asks for that shape, so a normal answer arrives already formatted rather than as prose the reader has to reorganise. **Log a mock** reuses the paste-extraction flow: paste a scorecard, parse it with AI (or the deterministic parser when AI is off), review the draft inline, and continue to the real form with every reviewed value prefilled — the panel itself never saves. **Plan todos** hosts the todo-assistance composer. Ad-hoc task requests in chat produce a suggestion card (title, due date, priority, category, notes, optional https link) that persists only when the user clicks **Add task**; a non-http link is stripped from the card with a warning. The coach never claims a task was saved.
- Prompt safety: user-controlled names (a custom exam, a tier label, a platform) and chat turns have control, bidi and zero-width characters removed before they reach a prompt, and every JSON data block is serialized with its angle brackets escaped so a stored value cannot forge a delimiter or a system message. The pasted report is the deliberate exception — it stays exactly as pasted, inside a fresh random tag for that request, because the extraction draft must reflect precisely what was read. The prompt states that all of these blocks are data rather than instructions; the escaping makes that boundary mechanical. A report that reads like an instruction is flagged in the review for human attention but is never obeyed.
- Todo assistance may send a bounded set of active personal todo titles, dates, statuses, notes, and subtasks, plus aggregate mock performance and the requested study-plan window, to the configured provider. This expanded context is confined to todo assistance, excludes Trash and account identity, and is disclosed before generation. Existing coaching privacy scope stays unchanged.

## Product principles

Keep logging quick and analysis readable. Use calm, direct language and a warm paper workspace with editorial typography, thin rules, clear tables, charts, and empty states. Dates are displayed in India Standard Time. Scores and percentages must retain their underlying meaning across different mock types.

## Implementation context

Next.js 16 App Router with React, TypeScript, Tailwind CSS, shadcn-style Radix button and dialog primitives, Motion, and Recharts. Persistence uses Prisma 7 with Neon PostgreSQL, dedicated schema `ssc_insight`, in project `lingering-mode-47457333`, production branch. Neon Auth manages Google sessions separately. An optional server-side AI layer uses an OpenAI-compatible Chat Completions endpoint; ordinary coaching is read-only, and the separate todo mode proposes explicitly reviewed personal-task mutations. Both are available when a user credential or server configuration is present. The migration starts empty and leaves Firebase data untouched. Database setup and credentials belong to deployment configuration, not client code or design documentation.

## Scope boundaries

This is a result tracker, not an exam-taking platform, coaching marketplace, marketing landing page, or account-management product. The AI coach is an optional in-app analysis aid, not a marketplace, tutor, or autonomous agent. Backup restoration supports reviewed merge and explicit replace; replacement is never silent and requires a current safety backup and confirmation naming the signed-in account.

## Private accounts

Google sign-in is required. Each user owns their mocks, analytics, comparisons, backups, and target setting. All data APIs verify the session and scope database queries by its user ID. There are no guest records, shared settings, or administrator views. Session failure hides private content, and account changes remount the workspace.
